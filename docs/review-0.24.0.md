# 0.24.0 审查与修复报告

审查范围：同一Goal程序终验、执行准入、来源与签名、配额/恢复、中文工作台及历史兼容。

1. 历史validator只有结构占位，没有可实际执行的程序复验路径。新增冻结validation_source，要求同Goal直接依赖、相同宿主判据、真实独立验收记录；保留裸历史节点待配置。
2. 业务并发已满时，已批准执行入口也拒绝verification通道，无法使用预留验证容量。修正为业务通道受业务上限约束，所有通道继续受总上限约束。
3. 首轮专项失败：CLI在终验runner之前抛出容器预检查异常。终验预检查交由受租约保护的runner记录人工处理状态；私有排队执行器预检查失败则持久记为blocked，不开始任务。
4. 新来源读取原本在另一个连接核对签名；改为复用当前事务快照，避免来源与验签记录跨快照。
5. 复用普通执行预览会让终验依赖生成模型配置，并误示“允许调用模型”。为validator单独绑定镜像/判据，完全不读生成模型文件；中文界面说明0生成预算与后续双签独立预算。
6. 中断测试首次预期不准确：执行期间撤销源程序会使下游epoch失效，旧工具回执无法结算，应为indeterminate并保留在途占额。核实该隔离是既有正确行为，修正测试预期，未放宽执行约束。原失败XML保留。
7. 浏览器首轮末项在进度异步刷新前读取文字，之前容器、新双签和Goal完成已通过；添加明确的完成状态等待后，从新目标重跑15项通过，首轮日志保留。
8. 公网运行首轮在配额写入拒绝断言停止，工具当时未记录原HTTP状态，原因未能确认。独立探测返回预期403；增强私有检查器仅保存方法/路径/状态码后，全程66项复测通过。未放宽权限断言或调整公网限制。

专项覆盖未验收源、伪旧式done、旧签名复用、双模型分歧/拒绝、跨任务来源、判据变化、重复尝试、缺快照提交、业务容量、HTTP角色边界、无模型配置执行、配额拒绝、暂停、未知工具及来源撤销。
