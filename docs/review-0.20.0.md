# Loom 0.20.0 审查与修复报告

第三轮已测试并发布后，检查当前默认体验发现原三节点流程仍包括角色候选及未完成validator，无法仅凭一个程序双签便诚实宣布Goal完成。本轮保留该流程，并新增具有真实完成条件的单程序体验：同一冻结需求和宿主测试、显式生成、独立复核、Gate-V、注册Goal判据逐层消费；不把占位节点改成done，不修改历史计划。

新增邀请/严格请求体/幂等/全局Goal上限反例和两模板共存测试。部署前备份且检查生成、复核两类队列；新增私有复核器受登记PID与命令路径校验保护。最终实际调用、浏览器、账务、恢复和公开GitHub结果补记。


最终真实新目标已在当前公网服务完成，不借用历史done状态：真实Flash生成、Docker6/6、两模型真实响应和两份真实签名、Gate-V及Goal验收均有持久事件。初次浏览器等待条件误判已保留，读取同一回执恢复测试且未新增请求。推进页遗留的全局“独立模型待配置”静态文案已更正，保留历史validator实际未完成状态。

审查后的边界：当前复核签名密钥在同一本机账号，生产职责隔离不成立；独立复核在私有账本执行，项目池全局限额与单请求占额已接通，不能据此称全部分布式/三层配额完成。恢复验证是新副本冷开与全部表行/事件一致，未执行生产回滚或投影重建。相关FR继续partial。
