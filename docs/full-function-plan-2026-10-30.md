# Loom 完整功能与前端重构计划

最新要求：持续开发直至满足策划书全部功能，完整测试后再更换桌面开发工具风格的中文前端。以functional-acceptance.json逐项记录原FR-001至FR-062的条文、依据、缺口及验收；不将小范围闭环当全部功能完成。原始Loom.md保持可追溯，实施修订遵循审查后的项目计划。

0.21.0已补三类文档复核与disputed，0.22.0补正常安装资源及版本化领域资产。0.23.0补审查意见质量的双模型验收与被审材料绑定；当前新链路是模拟模型与真实签名/基础设施测试，真实模型验收等待新密钥。七角色结构模板仍需实际输出与终验绑定，reviewer/validator的完整完成路径继续作为下一阶段前置项；随后接动态能力/评分派发、知识隔离/记忆、控制结构及生产能力。每项按真实来源和执行门槛验收，保留全部目标，不用结构模板审批代替执行成功。

1. 先补多角色真实完成路径：程序、需求、设计、公开测试候选都以原始材料盲审、真实双签、分歧仲裁和精确证据为准；结构校验不能冒充语义正确或执行用例。本轮0.21.0先完成三类结构化产物和disputed；新密钥到位前只做模拟模型与真实基础设施测试。
2. 接运行底座：版本化角色/能力画像、真实评分路由、共享原子预算/配额、通用Pack及策略资产；保留所有旧运行冻结版本。再接全部五种工作流控制结构与六修复原语，测试改图、撤权、循环熔断和下游失效。
3. 接知识与会话/任务/跨任务记忆，隔离写入、独立审核后召回；上下文按可达性、语义与token逐层裁剪并可审计。接通用工具中心、MCP三Server、Function Calling、声明式HTTP插件、统一出口与脱敏。
4. 补生产保障：OIDC/RBAC/节点授权、独立人工裁决/SLA、可续传事件流、快照恢复继续、指标/追踪/检查点、灰度回滚、黄金场景/内外评测物理隔离和四类鲁棒性演练。性能与规模按NFR实测。没有稳定服务器前继续本机受邀部署，不把临时隧道当生产托管已验收。
5. 全部功能验收与回归通过后重做中文工作台：窄侧栏管理项目与会话，中央任务会话及输入区，右侧按需展开计划/执行/差异/证据，使用克制的灰白配色、轻边框、紧凑工具栏和清晰状态。它属于开发工作台，使用产品表单、代码编辑器和画布组件的交互规范；不套营销页模板。保留Loom品牌、全部真实API/权限/预算/确认和手机适配，不做只换皮的假交互。

每个可验收版本：先测现状→记录/修复→实现→专项/必要全量/真实基础设施→发布扫描与GitHub逐字核对→下一版。每轮独立审查报告和真实调用记录。密钥按用户稍后提供的值固定保存在源码外后端私有配置，服务启动自动加载，前端不接触，公开仓库不包含密钥。
