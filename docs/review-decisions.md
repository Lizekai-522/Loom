# 审查处置与等待独立复核

0.17.1在既有审查候选上增加持久处置记录。适用范围为通过网关生成、已submitted的review-findings；来源记录不代表意见正确。第二模型仍待配置，本功能不代替独立验收或完整人工裁决。

## 中文工作台

打开`http://127.0.0.1:8796/console`，选择审查运行→候选产物→代码审查意见。核对正文、原代码subject、轮次、修订和摘要，再在“审查处置”中选择方式、填写理由、勾选核对并记录。

| 方式 | 条件和结果 |
|---|---|
| 保存待办 | 追加理由，仍待操作员；可以重新读取后继续处置 |
| 登记独立复核待办 | 仅no_findings可用；持久标为等待独立模型，不产生验收签名 |
| 批准单次修复输入 | 仅明确findings及同subject的未开始fixer可用；原子创建精确输入grant与处置审计 |

已完成路由后只显示历史，不显示空白的提交表单。只读身份可读取预览和历史；具名operator才能写入。review候选统一使用处置表单；原辅助输入预览仍可读取。旧辅助批准API保留兼容，但不会补造处置历史，预览会识别已有grant并禁止重复路由。

批准修复输入后，刷新目标上下文核对grant，再按[单次修复步骤](reviewer-execution.md)执行。记录处置不认领任务、不调用模型、不改变预算、不标记done、不修改硬依赖，也不授予验证或签名权。no_findings登记后原fixer/validator仍可能pending，完整独立验收编排留待后续实现。

## 接口与版本绑定

以`/v1/runs/{run_id}/artifacts/{artifact_id}`为前缀：

- `GET /review-decision-preview`：只读当前处置条件、候选reference、原代码subject、可选方式、fixer目标及preview_digest。
- `GET /review-decisions`：追加历史及对应审计摘要，最多32条。
- `POST /review-decisions`：具名operator与Idempotency-Key，正文为expected_preview_digest、decision、reason及仅approve_fixer需要的target_task_id。身份从认证取得，不接受自报成功、actor或签名字段。

decision使用`defer`、`await_independent_review`或`approve_fixer`。同一事务重新核对候选的计划、源任务/轮次、修订、正文与来源事件，原代码精确引用、运行/目标状态、硬依赖、未知效果和预留。状态变化或旧预览返回409，无部分写入。并发只有一个处置可使用同一预览；批准输入、处置记录、事件和回执一起提交或回滚。

历史追加不可更新/删除；读取时校验严格record schema与完整审计信封，缺投影或缺审计拒绝读取。31条defer之后保留最后一个名额给明确路由，达到32条不再写入；不允许用暂存耗尽最后路由名额。历史仍绑定原版本，源变更后可历史回读并显示失效，禁止新处置。

## 断线处理

提交结果不明时，当前页面保留完全相同的正文和幂等键，锁住字段；可刷新核对，或重试同一笔处置。已收到回执而后续读取失败时禁止再次提交，先刷新历史。已知409/权限/结构错误后先重新读取并核对，不能继续用旧预览。

切换运行、候选或重新连接会清理面板状态，迟到响应不会恢复旧目标。页面重载会丢失内存中的未确认幂等键，因此须先读历史与事件，不能盲目重发。此机制不承诺跨重启exactly-once。
