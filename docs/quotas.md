# 持久配额与限流

0.18.7 将租户和实际模型的滑动窗口次数、在途上限接入现有模型准入事务。模型使用 provider/model 作为资源标识，切换 route 别名不重新获得额度。配额与金额/词元预留、调用意图、上下文审计共同提交；失败共同回滚。次数统计准入尝试，不能当作供应商已收到请求的证明。

工作台“推进指引 → 准备本机执行”显示中文配额摘要，`GET /v1/quotas` 仅返回当前租户的限额、用量和版本摘要。读取不会调用模型或写账本，读取失败不授予执行权，也不阻断排队/取消；实际发起前再以数据库事务核对。受邀公网只能读取，不能改策略。

本机具名操作员通过下列入口配置，身份和模型秘密继续保存在源码外；配置不发送模型请求：

```powershell
python scripts/configure_quotas.py --help
```

按帮助提供现有私有数据库、身份文件、`configs/quotas.example.json`、租户、当前修订、幂等 key 和原因。策略及配置指令只追加、保留前一版本摘要；重试相同 key 读取原回执，不能回滚当前策略。首次登记的建表、标志与策略写入是同一事务，失败不留下半迁移。数据库启用后，未登记租户和缺失策略不能调用模型，直接 CLI 执行也不能绕过数据库的配置。

未知、部分或仍在途的调用继续占用并发名额，即使滑动窗口已过、进程重启、策略更新或路由别名变化。旧账本无法识别资源的未知调用按保守名额计算。只有原有具名人工核对流程将效果确认为已完成或未发送后，模型并发名额才随权威状态释放；旧准入次数仍保留到窗口结束。时钟回拨导致记录位于未来时拒绝新准入，不清空计数。

超限返回静态中文说明对应的 `QUOTA_*` 原因，并进入人工处理；不会自动等待后重发、退款、把任务判为成功或重置尝试次数。任务原有合同、金额/词元预算及独立验证仍生效。

本版本工具限额只登记在同一策略中，实际工具调用尚未接通该限额，接口明确返回 `tool_enforcement_connected=false`。后续版本接入 Python 容器测试并验证未知工具调用的保持与恢复。当前是单机 SQLite 的局部 FR-047，分布式供应商账户配额、生产身份及性能门槛仍未验收。
