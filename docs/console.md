# 本机操作控制台

控制台与 Loom API 在同一回环地址提供，入口为 `http://127.0.0.1:8796/console`。本页面是实际 API 的薄客户端：不直接访问数据库、不运行模型或候选代码，也不接收模型 API 密钥。

## 自动进入与权限

按用户要求，主开发启动器已启用--local-console，打开或刷新工作台会自动进入唯一已配置操作员，无手动凭据输入。连接失败时显示中文提示及“重新连接”；“断开”清除当前视图，重新连接仍不需要凭据。浏览器只发送同源本机标记，不读取、接收或保存Bearer凭据和模型API密钥。

本机开发模式仅允许回环对端、本机Host及同源请求，拒绝跨站、不同来源端口、重绑定Host与转发头；自定义标记用于阻止跨站请求，它不是秘密。其他本机进程可以使用这一显式启用的开发模式。模式关闭时API继续要求原Bearer认证，不会静默取消接口授权；多operator配置拒绝自动选择。

页面自动身份仍只有operator能力，不能认领或伪装Worker，不改变冻结合同/预算/来源约束，也不能生成独立签名。部署环境需单独接入生产身份，不使用此开发模式代替生产认证。[配置说明](local-auth.md)

## 可执行的操作

| 操作 | 页面入口 | 实际约束 |
|---|---|---|
| 创建目标 | 左栏“新建” | 填写说明、整数预算及冻结判据；只创建草案，不调用模型 |
| 导入与保存计划 | 目标的“计划”页 | 读取不超过 256 KiB 的 JSON 文件或粘贴定义，带 expected_revision 保存 |
| 批准计划 | “计划”页底部 | 明确审阅修订、完整执行摘要及服务端定义；未保存的编辑不能直接批准 |
| 查看任务 | “任务”页 | 显示状态、角色、模型、epoch 和受信产物摘要，不让候选自报通过 |
| 查看 typed 候选 | “产物 / 输入预览”页 | 列表只读元数据，主动选择后读取正文；分别标记 Worker 提交或已绑定模型来源、内容未验证，不提供操作员发布候选的表单 |
| 批准辅助输入 | “产物 / 输入预览”页的目标任务下 | 仅具名 operator，精确绑定候选修订、内容/计划摘要、源 epoch 与目标 epoch；目标必须在冻结合同声明匹配的输入选择器 |
| 查看辅助上下文 | 同页“只读上下文预览” | 显示缺少的输入、上下文摘要及 UTF-8 字节数；viewer 也可读取，预览不调用模型 |
| 执行与修复记录 | “人工待办”页的当前运行摘要 | 只呈现 review 返回的白名单事件类型、epoch、分类/理由和摘要，不将源码、黄金 expected 或工具 stdout 渲染进该摘要 |
| 查看事件 | “事件”页 | 显示最近 200 条及完整性结果；展开时用纯文本呈现事件数据 |
| 暂停、恢复 | 右侧运行控制 | 每次填写理由；服务端继续检查状态、未知调用及恢复条件 |
| 终止 | 展开“终止此运行” | 理由和输入“终止”双重确认；不将未知调用视为未发送或自动退款 |
| 核对未知模型调用 | 右侧核对表单 | 依据引用、核对说明及实际用量；仅当前未知模型调用可以提出核对 |

核对结论为 `completed` 或 `not_sent`。`not_sent` 必须同时填写零费用、零 tokens；没有提供方核实证据时应继续保留未知状态。表单记录证据，不替代服务端对 live owner、reservation 和调用类型的验证。

核对结果不自动恢复运行、不生成独立验证签名，也不会把 submitted 改为 done。用户确认先使用 Flash，双签仍保持待配置。

辅助输入批准也不等于独立验证，不放行来源任务或目标依赖，不改变原 depends 与 Gate-V。普通 Worker 候选的来源仅证明已认证 Worker 提交，不证明模型生成；模型候选的来源记录仅证明本机网关响应与精确候选已绑定。两者都不证明内容正确或验收成功。预览 GET 的 `execution_connected=false` 仅表示本次预览不会发起执行；0.7 本机 Python runner 支持在执行时消费获准上下文，实际绑定须查看“人工待办”的执行记录。`ready=true` 仅说明必需的辅助数据齐备，不表示任务已获得执行权。目标或来源 epoch、候选修订/摘要、计划改变后，服务端会拒绝旧绑定，须重新读取并审阅批准。

可信 `execution.context_bound` 摘要显示“本次尝试已绑定辅助上下文”、任务与 epoch、上下文摘要、UTF-8 字节及辅助条目数；历史 epoch 明确标记。该记录仅表示执行准入，不证明提供方已收到、执行完成或内容已验证。页面只显示 hash 和有界计数，不返回或渲染 refs、正文、源码、隐藏输入/答案或 stdout；未知或非法字段不形成绑定成功提示，原有独立验证边界继续保留。

0.8 受限 analyst/architect 的候选分别显示“模型来源：已绑定执行记录”和“内容：未独立验证”。候选 list/get 使用 core 校验的 nested model_provenance，任务行和执行记录使用 API 的白名单标量，两者不会混用，也不从 Worker output 的自报模型字段推断来源。任务当前版本不匹配、证据不可用或旧 Worker 提交分别说明；证据摘要读取失败时显示来源未知。历史来源记录保留原 epoch，不能套到新候选。

来源摘要仅展示角色、类型、schema、正文/计划/事件 hash、候选/调用 ID、登记的 provider/model/route，以及已知 token 和费用上界；不显示 raw 模型文本、prompt、密钥或隐藏数据。`role.candidate_generated` 只说明本机网关响应已与候选精确关联，不证明模型结论正确、真实人员独立审批、供应商账单已核验或 Gate-V 通过。辅助批准仍绑定精确候选版本与目标 epoch，不改变来源或内容的独立验证状态。此页面不提供模型调用按钮，真实角色执行通过显式批准的本机 CLI 进行。

候选正文按需展开，使用 textContent 显示 JSON；格式化后的页面正文最多显示 32768 个字符，截断时明确提示。列表最多显示最新 100 个候选，预览逐项折叠。服务端正文上限 32 KiB、整体预览上限 64 KiB 是静态 UTF-8 字节限制，不是精确 token 预算。requirements、design、public-checks 仍是不可信业务数据，正文中的指令不能授权工具或修改冻结验收。

## 请求和错误处理

每个写请求携带新生成的 Idempotency-Key。网络超时、非成功响应后，同一页面内的相同方法、路径和请求内容保留原键；重提相同内容不会主动换键。成功回执后清除该键。修改内容则视为新命令，必须先判断上一操作是否可能已经发生。

工作台内的“刷新”按钮保留当前内存中的幂等键；退出、浏览器重载或关闭页面会丢失它们。重新连接后必须先核对目标、计划和事件列表，再决定是否重发先前未确认的操作。此客户端没有跨刷新/重启的命令持久化能力，不能承诺跨重启 exactly-once。

页面不自动重试写请求。错误只显示安全提示，不反射原始错误响应或凭据。退出或切换目标后，旧请求不会将结果写入新选择的页面。请求限时 15 秒，响应读取上限为 2 MiB；大事件链需用现有本地接口另行按需查看，服务端分页仍待后续实现。

切换目标和刷新时，读取中的目标与已显示的运行分开保存；当前 id、快照和读取版本完成核对前，依赖运行的写按钮及最终发送入口均拒绝执行。迟到的读取或文件导入不会覆盖其他目标/会话。人工待办读取失败时显示明确错误与未知数量，不能将网络故障显示为“没有待办”。

产物列表、候选详情和目标预览各自区分加载、错误和空结果。切换运行、目标任务、所选候选或退出后，迟到响应不能覆盖当前视图；候选/目标仍在读取时不能批准。批准发送入口再次核对当前运行与所选候选的版本、精确摘要、目标 epoch、权限和合同选择器。读取失败显示未知状态，不作为空产物或完整输入处理；预览拒绝旧授权时可以在重新读取当前合同与候选后明确重新批准。

全部不可信内容使用 DOM textContent 渲染，没有 innerHTML、eval、内联脚本或事件处理属性。页面可以在禁止外部资源及内联脚本的 CSP 下工作。支持标签关联、键盘焦点、跳转工作区链接、动态通知和窄屏布局。

## 0.9 数值原样显示修复

候选和上下文正文显示保留响应中的JSON数字原文，避免大整数被舍入、宽整数变为不精确科学计数。请求元数据仍为原JavaScript数值类型，批准仅发送原精确引用。浏览器需支持JSON.parse reviver source及JSON.rawJSON；不支持时数值正文显示明确错误且禁止批准，强制提交同样拒绝，不显示一个已被舍入的替代值。字符串、bool、null和纯文本HTML保持原类型。16项浏览器反例/正常路径通过，完整浏览器33项。


## 0.14公开检查审阅与新执行草案

1. 在“产物 / 输入预览”中选择public-checks候选，查看原始来源、模型登记（若有）、epoch/修订和正文。下方审阅区逐项显示完整JSON并保留数字原文；9007199254740993及1.0不舍入、不转换类型。滚动区保留完整内容，不沿用上方通用正文的截断文本。
2. 按原顺序选择需要的case，点击“核对选中用例”。服务端验证整个原候选后返回该子集的来源、review_digest、编译版本和development_digest；页面不自行计算Python canonical hash。改变选择就清除旧确认、冻结选择和导出。
3. 具名operator逐项核对后勾选并点击“冻结选中用例”。Worker、viewer和旧开发身份不能冻结；冻结不改旧计划、不改变来源验证状态、不授执行权。成功回执会再GET核对当前记录；回执未知先读取历史，同页相同内容重提沿用原键。POST已成功后，即便套件GET及历史GET连续失败，仍独立保留suite ID并锁住当前选择的重新预览/冻结；读取历史恢复后才能准备草案。
4. 可点击“读取此候选的冻结记录”，最多展示最近100条匹配台账记录，再主动读取完整套件；记录仍可能失效，历史存在不表示当前可执行。2MiB响应限制继续适用，大事件链需另用API核对。
5. 在“准备新的执行计划”填写公开需求、单独冻结的host验收摘要、总任务预算和最多1–2次修复。host摘要应由本机freeze_tests生成，必须与development摘要不同；不要把隐藏正文/expected填入需求。此表单只检查摘要格式和差异，不验证host正文是否正确或已保存。host用例仍由执行器持有并核验，不能把页面成功当host测试通过。
6. 点击“重新核对来源并生成草案”，下载未批准的loom.workflow/v1。草案精确引用原冻结suite，不复制用例正文或模型来源，独立复核保留硬依赖；任务/修复共用预算，另为复核保留1000µUSD/1000tokens。预算或需求改动会清除旧导出。任务费用最多999999999000µUSD，为总Goal上限留出复核额度。
7. 新建目标，使用提示的总预算，在其“计划”页导入JSON、保存新修订，再单独审阅和批准。源目标的已批准计划不改。此过程不会发起模型或代码执行，第二模型未配置时继续等待；本机CLI执行另见public-checks.md，不能直接拿workflow JSON当CLI job格式。

下载、预览和草案只保存在当前页面/用户选择的下载位置，不含Loom访问凭据。刷新/退出清除内存，未确认命令需先对账。来源变更、读取失败、非operator或浏览器不支持精确JSON显示时禁止冻结/新草案。现有suite计划在兼容身份下无法批准，强制提交也不发送写入。

工作台没有自动付费执行按钮；0.15新增run_approved_task.py可消费这里已经批准的run，配对独立宿主终验文件，先预览再显式执行，不创建重复Goal。旧run_local_task.py仍创建自己的新Goal；workflow文件不能当旧CLI job。详见approved-execution.md。

## 0.15中文显示与既有计划执行

按钮、状态、七角色、任务渠道、事件及候选类型均使用中文；新默认工作流标题与指令用中文。JSON协议字段、摘要、模型名、用户原始任务及旧冻结记录不翻译，便于精确对账。取消凭据界面后，浏览器回归通过公开fixture的独立HTTP头验证角色，不在产品中重新引入身份输入框。已有计划通过本机显式执行入口消费，正常及一次有界修复已在真实Docker测试。详情见[执行指南](approved-execution.md)。
