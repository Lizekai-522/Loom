# 七角色推进指引与统一节点入口

0.17.2提供中文“推进指引”，并统一执行已批准计划中的analyst、architect、tester、developer、reviewer、fixer节点。validator展示真实待配置/依赖状态，当前不提供独立验证执行或成功旁路。角色入口统一不代表完整七角色产品链路已完成。

## 从工作台定位下一步

打开`http://127.0.0.1:8796/console`，选择目标→推进指引。七个角色始终显示实际任务数，未创建的角色为0，不把未分配角色伪装成已执行。每个实际节点显示当前下一步：

| 当前情况 | 操作去向 |
|---|---|
| 未批准/缺执行合同 | 审阅计划；批准后合同不可随意改写，必要时建立新计划 |
| 缺必需辅助输入 | 跳到正确目标的输入预览，有当前候选时一并定位供审阅 |
| reviewer已提交意见 | 跳到精确候选与审查处置历史 |
| no_findings | 显示不批准修复，进入原审查待办，不能假装跳过fixer后完成 |
| 输入齐备且未开始 | 准备本机执行；结构化节点显示当前预览摘要，Python节点还需独立冻结终验 |
| 已submitted | 查看候选或宿主证据，仍需独立验证 |
| 暂停/未知调用/未结算预留/已有尝试 | 进入人工待办核对；不自动重发、恢复或退款 |
| validator | 第二模型待配置，硬依赖仍明确显示 |

返回推进指引时重新读取，避免批准后继续显示旧待办。切换运行后迟到响应不能恢复旧目标；只读身份可导航，但不会获得输入批准、运行控制、执行或独立签名权限。

“准备本机执行”仅展示无凭据的元数据清单。页面不会调用模型、运行Python、改变预算或自动认领。当前实际启动仍由本机受控执行器完成，后续继续补工作台与执行器调度衔接。

## 统一入口

在项目目录使用项目虚拟环境运行。默认只读、不建数据库或重复Goal，不加载私有身份/模型配置，不调用Docker或网络：

```powershell
python scripts/run_approved_node.py --db '<现有数据库>' --tenant '<租户>' --run-id '<已有批准运行>' --node-id '<节点ID>' --expected-plan-digest '<当前计划摘要>' --report '<新的预览报告.json>'
```

developer/fixer额外提供`--tests-file '<本机冻结终验.json>'`，格式为仅含tests数组的UTF-8 JSON。摘要必须与批准计划匹配。结构化四角色禁止携带终验文件，防止误将隐藏判据当作模型输入。

执行同一节点时保留上述参数，加：

```powershell
--execute --preview-digest '<重新读取的当前摘要>' --identities-file '<本机私有身份JSON>' --secrets-file '<本机私有模型JSON>' --model-config configs/models.example.json
```

Python节点再加`--sandbox-image 'sha256:<已批准不可变镜像ID>'`。报告换新文件，不能覆盖输入或写入模型私有目录。密钥内容不出现在命令、报告、页面或容器中。默认输出上限1024tokens，预留按冻结预算和现有保守费率上界计算，费用不是供应商账单。

准入要求唯一同租户operator/worker和具名计划批准、open运行、pending/epoch0、真实硬依赖done、没有既有/未知effect或该任务旧预留，预算与容量均够。存在辅助输入时把上下文和精确grant摘要纳入预览，并在认领同一事务为epoch1重新批准，不无条件沿用epoch0。读取/审批/返回/提交继续复核源版本。重入、漂移、审计失败与并发冲突拒绝或完整回滚。

执行按冻结角色自动选择结构化RoleTaskRunner或Python LocalTaskRunner；支持原审阅套件及Rebind、普通有冻结宿主摘要的developer、精确意见批准后的单次fixer。旧CLI继续兼容。单次fixer失败仍转人工，已知响应结算，未知调用保留预算，不自动重试；成功仍submitted。
