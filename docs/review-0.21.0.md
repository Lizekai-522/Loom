# Loom 0.21.0 审查与修复报告

起点0.20.0源码与公开仓库一致。新鲜基线123主测试＋38子测试通过，无新模型调用。旧临时地址DNS失败，已确认当前登记隧道日志为Tunnel not found，备份私有访问配置后只替换该隧道，未停止API或Worker、未改访问码或数据库；新地址登录页200。私有恢复脚本模板重复UTF-8 BOM导致首行设置报错，实际恢复流程完成；准备器改按utf-8-sig读取并剥离重复BOM，原日志保留。

功能审查发现旧独立复核只接受developer/fixer的Python产物，多角色中的需求/设计/公开检查无法真实完成；现对三类候选重建已结算模型来源、类型schema、当前版本/claim/提交及完整事件链，再生成v2精确引用。两模型只接原始材料与冻结需求，不互见首签意见；真实验签后复用Gate-V完成当前Task。

格式验证计数为零执行用例，不写入虚假host测试。Goal要求tests.pass却无实际程序时保持未验收；schema.valid/report.traceable满足且全任务签名通过才可成功。完成后的历史角色来源和正文保持可读，旧program引用/v1签名字段不变。文档ref不能作为程序fixer授权。

同时修正模型分歧语义：一通过一拒绝记disputed并保留签名进入人工，两个拒绝才是rejected；旧历史状态不改写。通用独立人工裁决、动态角色与工作流控制结构等继续按62项追踪。前端只增加必要功能入口，本轮没有提前将界面换皮当全功能完成。

补充审查发现旧角色来源摘要把已完成Goal的原始候选都视为不可确认，完成后的来源提示与真实任务状态冲突。现在保留其可验证历史来源，消费与新授权仍按原失效检查；正文/版本导出每次重新核对精确内容。准备发布脚本还纠正README历史体验链接的匹配并支持已完成步骤幂等恢复。下一组优先核对普通wheel安装的领域包资源路径及版本资产，防止只在源码可编辑安装中可用。

首次升级预检遇到已有复核记录时，维护连接返回普通tuple，复核读取器按字段名访问而误报台账无效。实际记录没有改动，预检在停进程前失败，连接已回滚；修复为sqlite3.Row后重新执行完整台账验证，未放宽任何证据检查。空复核表的旧升级没有触发此问题，原失败输出保留。
