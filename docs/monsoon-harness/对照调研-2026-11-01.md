### 1.2 架构要点（全部带一手证据）

- **Router 不是进程，是常驻模型会话**：id 存 KV `runtime.masterId`（`src/kv.ts:33`），启动时确保存在并绑定 preset（`src/app/runtime.ts:121-124`）；KV 是 SQLite 单表（`src/app/store.ts:64,164-181`）。
- **决策输入是卡片不是原始消息**：Trigger 卡、Thread、related_tickets（≤8）、handed_back 原因；截断常量 600/1500 字符（`src/executor/dsh.ts:107-109`）；输出走 14 个 `orchestrator_*` 工具，`orchestrator_route` 一次 1-20 条 accept/attach/stop/ignore（`src/app/tools/main.ts:122-279`）。
- **Mandate（工单级可携带凭证）**：`{ strength, policyVersion, basis, actor, scope }` 不可变（`src/core/model.ts:126-133`）；accept 时从 Evaluation 固化、随工单 JSON 持久化（`src/core/evals.ts:311-325`、`src/app/store.ts:233-235`）；注入 worker 系统提示词限定范围（`src/executor/dsh.ts:114-120`）；**恢复/attach 前按当前策略重校验**（`src/policy.ts:213-240`），失败保持 ended、消息转重新研判。策略变更不撤销在跑工单，而是计算 `policyEffects` 定向通知（`src/policy.ts:144-165`；`dsh.ts:141-150`）。
- **durable effect 队列**：先存储后执行、kind/key 合并、`Later`（暂时不行≠失败）语义、generation 防覆盖（`src/app/effects.ts:46-66,130-146`）。
- **事件不落盘**：emit 只是注入 Engine 的回调（`src/core/engine.ts:31`），"Other events currently have no consumer"（`docs/007-architecture.md:109`）；无游标、无回放，可回放的只有聚合快照与 effect 队列。
- **准入 gate 是纯函数**（`src/policy.ts:191-211`），只有 inferred 候选的"研判"交给模型；observe 档照常研判但只记 `would_accept`（`policy.ts:55-57`）。
- **提示词纪律**：固定组装顺序 + policy 段最后注入（`docs/004-prompts.md:44-59`）；五层强弱序，外部文本一律视为数据（`docs/004:65-71`）；提示词版本化 + 会话只能读自己跑过的版本（`src/app/sessions.ts:329-339,202-204`）；反注入句式（`prompts/admission.md:5`）；noWait guard 禁主会话等待（`sessions.ts:70-86`）。
- **worker 隔离**：每工单独立会话+目录+worktree（prepare 上限 10 分钟，`docs/003-execution.md:49-53`）；工单结束 guard 拒一切工具（`sessions.ts:293-296`）；六态结构化汇报 progress/waiting/ready/blocked/failed/dropped + `human_action` 结构化提问 + `question_for_trigger_id` 回路由到当事人原消息（`src/app/tools/executor.ts:75-105`）。

### 1.3 对 Loom 的吸收清单

| 机制 | 证据 | Loom 现状 | 评级 |
|---|---|---|---|
| **Mandate 任务级授权凭证**（strength/basis/policyVersion/scope 随任务固化，恢复前重校验） | `model.ts:126-133`、`policy.ts:213-240` | 全局静态能力集（`src/loom/auth.py:20-26`） | **高**：与 Loom lease/epoch 同构（policyVersion≈epoch），把"谁、经何路径、何范围、何策略版本"变成任务自带、可验证、可过期的凭证 |
| **observe 灰度档**（只记录 would_accept 不执行） | `policy.ts:84-87,55-57` | 无对应档位 | **高**：自动化灰度上线的标准动作，可作为准入第四态 |
| **策略版本化 + 变更通知制**（不撤销在跑任务，恢复时重校验 + 定向通知） | `policy.ts:111-118,144-165` | epoch 有，变更对在跑任务的效果未细分 | **高**：比一刀切取消干扰小且可审计 |

| 调度输入最小化纪律（卡片化/截断） | `prompts/shared.md:5-6`、`dsh.ts:107-109` | Loom 调度器是确定性代码 | 中（若未来 LLM 参与调度/摘要时直接适用） |

### 1.5 明确不吸收（与我们的拍板/更强机制冲突）

1. **worker 无审批执行 + danger-full-access**（`docs/003:27`、`sessions.ts:152`）——与"不做自动批准"直接冲突；Loom 的审批闸门是强项，不能反向退化。
2. **阻断命令清单当边界**（`docs/003:80`）——自认可绕过；ms 的命令管控放宿主中介层（文件根+放行检查+绊线），shim 只当易用性默认。
3. **事件不落盘无哈希链**——Loom 信封（前序哈希+链校验）严格更强，不为省一张表退化。
4. **LLM 常驻会话做唯一调度器**——只吸收"调度输入最小化"，不吸收"模型决定派工"；Loom 确定性调度器在可审计/幂等/预算上更符合定位。
5. **auto-merge 等提示词治理**（`docs/003:84-90` 明言只是提示词）——合并类动作必须过 Loom 信封，不靠模型自觉。
6. **无界存储**（`docs/007:484` 自认）——ms/Loom 需要保留与归档策略。
7. **auto 档 inferred 自动接单**（`docs/002:99`）——无 Loom 式审批链的系统里等于自动批准；ms 的 proactive 能力必须挂"记录不执行"档。

### 1.6 文章 ≠ 实现（别把文章当规格）

README 自认与论文实现不一致、"部分设计是未来方向"（`README.md:3-5`）；`docs/007` 事件清单漏 `trigger.followup`（文档自身有漂移）；`docs/007:614-617` 留有 Open questions（Trigger 字段信任边界、部署隔离）；合并治理/审批流完全是提示词层、无代码强制；原型是单提交快照，无演进历史。**该原型是研究快照，其价值在机制形状，不在工程成熟度。**

## 二、dsh 产品仓功能点（52 包扫描）

产品核心是**会话与上下文域**：仅追加事件日志是唯一真源、消息历史从日志派生（`docs/subsystems/session.zh.md:5`）；spill 溢出（`spill.zh.md:92`）、compaction 压缩（三事件锁 start/summary/end，`compaction.zh.md:15-19`；pressure/overflow 双触发，`:80-84`）、session-query 跨会话 SQLite 全文检索（`session-query.zh.md:5`）、goal 生命周期（四态+机器可路由阻塞码，`goal.zh.md:25-55`）、plan 计划模式与评审退出（`plan.zh.md:5,33`）。

产品独有卖点：宿主级 schedule（7 种时间类型含 RFC 5545 RRULE 子集与 Vixie cron、追赶只补最新、三种投递目标，`schedule.zh.md:5,27-34,80-84`）；subagent 统一 activation API（能力标记协商 + outputSchema + maxDepth + delivery: parent/caller，`subagent.zh.md:20-44,109-116`）；deliverables 轮次交付物（present 声明 + git 快照 diff，非 git 目录也覆盖，`deliverables.zh.md:5,26-45`）；guard 循环卫生（重复调用提醒 + 工具超时强制，默认启用，`packages/guard/README.zh.md:11-15`）。

CLI/形态：`dsh` 唯一启动器 + profile 制；`dsh web` 默认 3080（`apps/cli/reference/README.md:30`）；`--profile headless "job"` 一次性任务（reasoning→stderr、答案→stdout、语义化退出码，`reference/README.md:44`）；配置分层 patch、后层整体替换（`reference/README.md:11`）；凭据只写不回读、UI 只见脱敏描述符（`docs/user/guide/providers.zh.md:13`）。

**20 条功能点候选**（详见代理报告，按"审计价值/成本"排三批）：
- **第一批（低成本，建议 Phase 1 就进）**：guard 循环卫生、spill 溢出、时间上下文注入、headless 一次性运行、凭据只写+env 优先级、ask-user 提问 seam、消息级反馈落日志（不进模型上下文）。
- **第二批**：compaction 三事件锁状态机、压力+溢出双触发自动压缩、deliverables 轮次交付物、宿主级 schedule、plan 计划模式+评审退出。
- **第三批**：session-query 跨会话检索、subagent 委派契约（outputSchema/maxDepth/delivery）、goal 生命周期+机器路由阻塞码、技能渐进披露（目录进提示词、全文懒加载）、MCP 客户端面（stdio+Streamable HTTP、工具名服务器前缀）。
- **单独亮点**：沙箱三模式 + **`full|partial` 强制完整度诚实上报**（`sandbox.zh.md:11-38`）——"承认部分强制比假装强制更安全"，直接呼应方案书拍板三的三条命题写法；会话 fork/seed 血统（`inheritedEventCount` 进快照，审计可分辨继承 vs 新产）；配置 JSON Schema 导出。

**明确不吸收**：extensions 运行时自修改（被审计对象不能改自己的运行时组合）、workflow 模型写编排脚本（编排权在 Loom）、agent-team 实验性隐式团队、computer-use/browser-use（Phase 1 不需要，未来走 MCP）、ptc-runtime、bundle 多 profile 全套、ACP、Electron 壳。

## 四、合并结论：候选功能清单（供拍板）

**A 组：机制级（来自 super-agent，建议写入批次范围）**
1. Mandate 任务级授权凭证 + 恢复重校验（Loom 批次三新增子项候选，高）
2. observe 灰度档（Loom 准入第四态，高）
3. durable effect 意图队列（与批次三副作用登记端点合并设计，高）
4. 六态汇报 schema + human_action（ms→Loom 汇报协议，高）
5. ms 调度器/执行器分层 + 每任务独立目录 + 不等待纪律 + 工具生命周期 guard（ms 批次二设计约束，高）

**B 组：功能级（来自 dsh，第一批低成本）**
6. guard 循环卫生、7. spill、8. 时间上下文注入、9. headless 一次性运行、10. 凭据只写+env 优先级、11. ask-user 提问 seam、12. 消息级反馈落日志

**C 组：功能级（第二批，Phase 1.5 候选）**
13. compaction 三事件锁、14. 双触发自动压缩、15. deliverables 交付物、16. 宿主级 schedule（可加事件触发）、17. plan 模式+评审退出

**D 组：功能级（第三批，Phase 2 候选）**
18. session-query、19. subagent 契约、20. goal 生命周期、21. 技能渐进披露、22. MCP 客户端面

以上均为**候选**，未拍板不进批次范围；A 组建议随下一轮策划会拍板。沙箱 `full|partial` 诚实上报作为写法纪律即刻采纳（并入拍板三的表述规范）。
