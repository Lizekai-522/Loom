# 私有副本恢复与冷启动检查

摘要的 `manual_review_required` 只表示恢复相关的在途或未知状态是否需要核对，不表示候选或 Goal 已完成独立审阅。

0.18.4 提供 `scripts/check_recovery.py`。工具只读打开现有 SQLite 数据库，在一个读取事务中核对一致快照并创建新的私有副本，然后用独立 Python 进程重开副本；不会覆盖来源，也不启动 Worker 或发起模型调用。

在源码目录执行，按实际位置替换路径；报告必须是尚不存在的 JSON 文件：

```powershell
..\..\work\loom-venv\Scripts\python.exe -X utf8 .\scripts\check_recovery.py --db ..\..\work\loom-first-round-api.db --work-root ..\..\work --report ..\..\work\recovery-main-result.json
```

公网体验库可使用 `..\..\work\loom-public-preview\preview.db`。每次会在私有 `work/loom-recovery-checks` 下建立新目录，保留副本和校验元数据；该目录含完整业务数据，不加入源码或公开附件。工具拒绝在当前公开输出目录内创建副本，不覆盖既有报告。

检查包括 SQLite 完整性与外键、每个 run 的连续事件链、全部业务表行与账务、恢复前后的 schema，以及执行请求的审计绑定与历史。正在排队的请求仍排队；正在运行或有未知调用/预留时，摘要提示需要人工核对，不自动认领、重试、退款或释放预留。在线来源在备份期间可以继续合法写入，副本使用备份时固定的读取快照。

JSON 摘要只含检查状态与数量，不含任务正文、身份令牌、私有路径或原始事件。失败时保留副本供排查，返回固定错误码。演练副本不会复制执行器配置和心跳。

本工具核对的是完整数据库副本的冷开读取，不从事件重建所有投影，不证明独立签名检查点、远端备份、任意历史时间点或灾备切换。需要替换实际服务数据时，应另行停止写入、核对在途调用并演练回滚；不能直接用本工具覆盖在线库。FR-043 仍为部分实现。
