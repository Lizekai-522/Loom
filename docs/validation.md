## 有意义的拒绝和故障路径

- 同键异参/异操作拒绝，并发同键同参只创建一次。
- 数据库提交后进程边界仍能投递 outbox，确认丢失后重投通过 inbox 去重。
- 同一任务并发认领只有一个赢家，业务任务不能占用验证保留槽。
- 过期/失效/被替换的 claim 无法完成任务或取得新的外部发起权。
- 并发预算预留不能超出账本额度；超预留实际用量被记录，run 挂起，新发起被阻断。
- 未决副作用阻止结果提交和自动重发，逻辑调用标识不存在分隔符碰撞。
- 任务失效传播到下游并撤销 epoch；外部效果不会因图失效被记为撤销成功。
- 修改事件类型、操作者、租户、run、序号可检出；给定独立预期链头/数量时可检出截断。
- 非成功双签、签名版本错配、伪造信任标记、重复验证者或缺少独立模型均被拒。
- Worker 自报 `verified=true` 仍只进入 submitted，下游保持阻塞。
- 验收未通过或任务未验证完成时，不能把 Goal 标为成功。
- API 按 token 解析租户；跨租户 ID、额外 tenant 字段、未注册判据/规则和非严格预算输入被拒。
- 嵌套非有限数值收到安全的 422，错误响应不回显产物正文。
