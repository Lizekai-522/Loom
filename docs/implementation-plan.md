项目已完成首轮 S1-local 建设，**S2 仍进行中，S3 已取得首个受限真实执行证据**。当前 API 与任务内核继续使用单实例 SQLite；真实 JetStream、独立 PostgreSQL 16.15 DDL/RLS 和本地 Ed25519 检查点保持独立边界。本轮新增 Goal/Plan 审批、七角色冻结合同、Flash 网关与 Docker Python JSON 执行器。方案修订、局部实现、真实探针和完整需求验收分别登记。

- **设计修订：** 桌面 Loom.md 已按 R01–R24 修订为 v2.1 实施基线候选；文字改正不表示架构复审或生产验收通过。
- **已实现源码：** 原内核、消息与检查点组件，以及 workflow/model_gateway/sandbox/execution 模块。Goal 草案不能执行；保存计划产生 revision/digest；批准当前审阅版本后原子创建冻结合同任务。PostgreSQL 仍只有独立 schema/角色验证，尚无运行时 Store 适配器。
- **本轮测试：** 完整分阶段数量详见最新 [验证记录](validation.md)。套件使用真实 Docker/NATS/隔离 PostgreSQL，网关使用 Mock；真实模型探针单独登记。0.2.0 历史为 112 项本地 + 23 项基础设施 = 135 项通过、0 跳过，另有 33 个参数子测试，不作为 0.3.0 最新总数。
- **API 状态：** 沿用原启动器、首轮 SQLite 与 tenant token，已升级 0.3.0；原 9 项及新 Goal/Plan 12 项实际 HTTP 检查通过。本机地址 127.0.0.1:8796/docs，health stage 仍为 S1-local；仅有租户 Bearer，未完成 OIDC/RBAC、职责分离或 HTTP 执行接口。
- **真实执行：** Flash 返回的 Python JSON 程序在 Docker 中通过 4 个宿主黄金用例，usage=417 tokens，费用上界记账 247µUSD，非供应商账单。任务为 submitted/awaiting_independent_models，run 仍 open；没有将一个模型伪装成双模型，没有声称七角色全链或 Goal 成功。
- **生产待验证：** 独立双模型及受信签名、完整工作流/人工闭环、最小上线认证授权、完整 PG 命令、多主机、NATS accounts/TLS/R3、生产沙箱/出口代理、远端锚定、真实业务写恢复与容量/SLO 仍有待完成。

依赖复用取舍见 [GitHub 复用记录](github-reuse.md)，已安装依赖的归属见 [第三方声明](third-party-notices.md)。FastAPI/Pydantic 用于接口，nats-py 用于真实消息适配，cryptography 用于真实 Ed25519 签名/验签，psycopg 用于隔离 PG 检查；Temporal、LangGraph 没有作为运行内核接入。[本轮验证](validation.md) 分别列出实测和剩余边界。

## 阶段依赖与可测出口

路径为 **S0 → S1 → S2 → S3 → S4**。S0/S1 中互不冲突的文本修订、类型契约与测试可以并行；真实模型与外部动作的开放必须等待其依赖机制通过。

### S0：设计契约与审查修订

交付：v2.1 候选方案、24 项修订对照、唯一 ADR 索引、事件信封/状态机/预算/副作用决策表及本路线。

出口：

1. R01–R13 的设计决策明确，成功、例外、停滞、未知态互不混用。
2. R14–R24 均有处理方式、所属模块及可测验收，不再保留互相矛盾的承诺。
3. 规范区分本地适配器和生产契约；指标的分母、负载与起止点可执行。
4. 核心拒绝路径先形成测试；文本已修订与系统已验证分开登记。

### S1：单主机确定性内核

依赖：S0 核心状态和信封契约。

交付：单机 SQLite 适配器、API、结构化任务书、Gate-P/V、事件/回执/outbox、claim/epoch、通道容量及预算预留；提供不需要模型密钥的正常/拒绝路径演示。

出口：

1. API 可创建 run/任务、认领与提交；OpenAPI 正常生成，租户 token 和幂等键作为预期 Header 工作。
2. 同键同参取回同一回执；同键异参/异操作拒绝；并发请求不能重复创建状态。
3. 已提交输出保持 `submitted`，不因 Worker 自报完成而打开下游依赖；只有受信验证入口才能完成验证。
4. 非成功双签、旧版本签名、过期 claim、跨租户资源 ID 被拒绝。
5. 业务满载时验证预留仍可用；并发预算预留不超过本地账本余量。
6. 持久投影与纯回放对照至少覆盖任务提交/拒绝/重试、预算、失效和未知副作用；字段差异必须修复或明确超出当前子集。
7. 文档运行命令在干净本地数据库中实际执行，并保存测试与演示结果。

### S2：故障矩阵与真实基础设施适配（进行中）

依赖：S1 的事件/outbox/claim/预算契约。PG/NATS 检查使用便携原生进程与新建 loopback 数据目录；本轮另已启动 Linux Docker，并验证首次生成代码执行所需的最小隔离。这个本机子集通过后才执行了 Flash 候选，不外推为生产沙箱验收。

历史子集证据包含 PG DDL/RLS 14 项、JetStream live 8 项、broker 强杀/同目录重启 1 项，以及检查点 37 项和 JetStream 10 项单元测试。本轮新增真实 Docker 隔离、工作流及受控网关回归，完整数量详见最新验证记录。NATS 回归覆盖跨租户同 durable、同 scope 不同 AckWait 的并发创建；强杀后 ACK floor 可能回退，依靠持久 inbox/游标防重复效果。`scripts/check_s2.py` 要求不可变 `--sandbox-image`、NATS URL、原生 server binary 和私有 PG config 四项配置，每阶段清除旧 JUnit，拒绝跳过、零用例、缺失/无效报告或失败。模型网关使用 Mock，真实模型探针另存。

这没有完成全部出口：完整 PG Store、跨主机容量/预算、业务外部动作/RPO、生产执行隔离和独立远端锚定仍在进行。首发继续使用 SQLite，不以部署 PG 集群作为本机功能链路的前置；规模扩大前必须补齐对应不变量验证。

交付：生产数据库迁移与角色、JetStream 适配器、受信网关接口、持久化人工队列及恢复决策矩阵；同时前置交付首次代码执行必需的最小沙箱、出网 scope 限制、任务凭据隔离和受信测试报告来源校验。S4 继续生产隔离加固，不承担首次引入隔离。

出口：

1. 数据库提交后、发布前退出可恢复；broker ack 后本地标记前退出允许重投，但消费者只应用一次。
2. 两个调度实例竞争同一任务、最后容量及最后额度时，全局不变量成立；旧实例不能继续取得新发起权。
3. 外部写桩在发起前/已送达/响应丢失/完成记录前分别退出，产生正确的未发起、已完成或不确定态。
4. 恢复到可能丢失发起记录的时间点时，写动作被冻结并核对；不能把“无记录”直接解释为“未执行”。
5. PostgreSQL 集成测试使用真实受限角色，覆盖跨租户引用、RLS、审计范围与对象访问。
6. 独立链头/事件数检查点能够发现截断，不能只复算当前数据库后返回 `valid=true`。本轮本地 Ed25519 子集已验证；同一账号控制全部文件仍不抗整体回滚，生产需独立信任存储与权限部署。
7. 最小代码沙箱验证只读根、任务专用可写区、非特权执行与资源限制；越界读取、未授权出网和跨任务残留状态不可使用。测试使用隔离环境中的受控样本，不以宿主进程直接运行生成代码。
8. 工具/模型调用只取得任务所需凭据，不能读取其他任务或租户凭据；受信测试报告来源、代码/测试版本和内容摘要均可验证。上述隔离与来源检查未通过前，不进入 S3 的模型生成代码执行。

### S3：首个 software-dev 场景与收益证据（受限真实探针已完成，整体进行中）

依赖：S1/S2 相关安全与持久化检查，尤其 S2 最小代码沙箱、出网 scope、任务凭据隔离及受信报告来源实测通过；真实模型联调另需提供方配置和预算。不能因仅运行在本机便跳过执行隔离。

已完成的真实链路仅为 Python 标准库 JSON 程序：宿主冻结用例及摘要，经批准合同路由 Flash JSON mode，再把候选送入无网络 Docker，宿主核验输出后提交。执行器只接受获准 developer/fixer；当前脚本构造 implement → independent_review 两节点，实际只执行开发节点。默认七角色模板仍为规划能力，不表示七个角色都已真实跑通。

2026-10-23 的真实探针通过 4 个黄金用例，usage=282 输入+135 输出=417 tokens；247µUSD 为固定价目上界记账，非账单。submitted/awaiting_independent_models、counts_as_success=false、full_workflow_completed=false，验证节点仍被依赖屏障阻挡。下一步接通独立模型、受信验证和修复/人工流程，再扩大到真实仓库软件修改；不把同一模型多角色配置作为双模型结果。

交付：精简 `software-dev` Pack、版本化验收/测试集、受信测试结果、独立验证与失败修复分支。

出口：

1. 相同输入与 fixture 可演示通过、测试失败、补证、旧签名拒绝、预算耗尽和人工例外。
2. 真实测试结果由受信工具生成，绑定仓库版本、任务尝试、测试集与产物摘要；模型不能直接填写受信覆盖率和通过标志。
3. 真实双模型仅接收允许的原始证据，身份由网关确定；没有两个模型时明确挂起，不能用固定布尔桩宣称双模型完成。
4. 独立 held-out 场景按难度分层，和单 Agent、固定流程使用可比任务与资源；报告失败、超时、人工工时和总成本。
5. 如果复杂编排没有证实收益，调整适用任务和流程规模，不能用内核单元测试通过替代业务效果结论。

### S4：生产化与第二领域验证

依赖：S2 故障与隔离矩阵、S3 场景效果、基础设施和团队运维责任。

交付：认证/授权与独立 Worker 身份的生产扩展、沙箱/出口代理加固、审计签名、告警/Runbook、备份恢复、压测与灰度；再引入第二 Pack 验证领域中立。首发所需最小 OIDC/RBAC 与职责分离不能因列在生产阶段而后移；最小执行隔离已在 S2 本机子集实测，S4 负责生产加固。

出口：

1. 明确的容量模型与硬件下达到延迟/吞吐/SLO；同时报告平均负载、峰值与 180 天保留成本。
2. 真实出口默认拒绝未授权目标，无法绕过租户/任务预算和作用域，敏感凭据不进入事件或模型上下文。
3. 完成月度恢复流程演练，验证投影、外部效果和审计链，明确达成的 RPO/RTO。
4. 第二领域通过同一内核契约与一致性套件接入；无内核业务分支改动，且不依靠相同自评场景证明通用效果。
5. 所有已接入依赖固定发行版本，保留许可证/SBOM/来源；灰度与回滚不破坏在途 run 的版本语义。

## 状态登记规则

本地 API 与 sqlite 文件只用于本阶段受控开发。生产开放、真实外部写、付费模型并发和跨租户部署应分别通过上述相应出口，再扩大范围。
