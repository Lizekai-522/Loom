# Loom 晚间前端与云端准备审查报告

本报告记录 0.26.0 的实际变化、失败及上线缺口，与旧版审查分开保存。

## 已修正

1. 旧首页突出“连接本机工作台”，不适合独立网页体验。改为自动进入的中文项目空间：最近项目、需求输入、项目概览、计划、执行、产物与独立复核。会话内容取自需求和真实任务台账，不生成虚假的执行进度。保留所有原有权限、预算与确认。
2. 程序自动聚焦工作区时页面滚动，顶部导航被遮挡。改用 preventScroll 并验证桌面/手机视口。
3. 真实 Flash 复核返回结构有效但来源任务 ID 不一致。原结果被系统拒绝，首次失败保留；提示增加服务端核对过的完整来源 JSON，并明确引用规则。增加当前审查任务 ID 冒充被审来源的拒绝回归，未自动补写模型结果或生成签名。新审批目标随后真实双签成功。
4. 原复核完成后顶层运行状态需要手动刷新。现在在读取到终态且任务状态变化后触发只读刷新；不新增执行或重试请求。浏览器已核对自动显示“已完成”。
5. 缺少可复用 Linux 部署入口。新增私有初始化、单并发持久配额、实际加密签名密钥生成与 systemd/Caddy 安装说明。拒绝已有状态覆盖；API 仅监听回环，只有执行器获得 Docker 访问组；真实模型密钥不进入源码和命令行。安装器核对域名、配置、冻结用例与不可变镜像，不自动改写全局代理或开放公网。

## 检查中发现的测试问题

浏览器脚本曾使用不存在的可见性方法、未配置的相对 API 地址和过期页面文案，均保留失败输出后修正，未重复发起已经提交的模型请求。升级对账首次使用“所有表行必须完全相同”的旧条件，被新建测试草案触发；改为逐行验证原记录不变，并明确核对新增草案。最终旧数据逐行保持，无删除或改写。

Linux 检查容器首次漏带 packs/configs 源包资源；补齐与交付源包一致的只读挂载后，5 项初始化和权限检查通过。尚未把本机 systemd 脚本语法检查等同于实际云端服务运行。

第二轮完整回归中，心跳丢权故障注入用例的两秒外层等待超时；日志显示调用派发前的同步准备占用事件循环超过两秒。该用例已使用“请求已派发”事件触发丢权，外层计时却包含了数据库准备。改为在限定调度轮次内验证故障触发、取消完成以及未知计费保留，避免把机器磁盘准备延迟当作租约机制失败。生产租约、心跳周期、Docker 五秒时限及所有未知调用不退款/不重发断言保持原值。原失败 XML 保留，修正后的专项和完整回归单独登记。

封装前再次发现 Docker Desktop 与临时隧道进程退出。使用已验证的私有缓存启动方式复用原数据盘恢复 Docker，未删除镜像或卷；额外12个输入边界在原五秒限制下全部通过，原目标合同与验收结论不改写。临时隧道已按登记进程恢复，旧地址失效，新地址保存于私有访问信息文件，访问码不变；这次中断再次说明临时本机入口不能代替独立云主机。进程退出的根本原因尚未独立确定，不能把一次重启写成永久修复。

最终测试数量、模型调用、预算及完整回归状态见 [验证记录](validation-0.26.0.md)。所有早期失败均保留，不能把等待超时或模拟提供方写为真实验收通过。

## 尚不满足的上线条件

- 尚无云主机，当前入口依赖个人电脑。需要购买主机、配置 HTTPS、部署并在个人电脑关机后独立网络验收。
- 当前仍是受邀共享测试空间，没有完成生产多用户账号隔离、完整灾备和容量门槛。
- 原 62 项尚未全部通过；新增前端不会补齐尚缺的调度、记忆、通用工具或完整七角色修复功能。
- 自定义需求先保存草案，执行计划仍需审阅；当前完整公网模型验收覆盖已配置的词频 Python 场景，不代表可执行任意软件项目。

## 购买建议与下一阶段

建议专用 Linux 云主机，Ubuntu 24.04 x86_64、2 核 4GB、至少 40GB SSD，优先香港或新加坡；2GB 仅用于限制并发的低负载试运行，容量须在目标主机实测。

2026-10-30 查阅[腾讯云国际站官方产品页](https://www.tencentcloud.com/products/lighthouse)：2 核 2GB/40GB 为 $4.2/月，2 核 4GB/90GB 为 $8.5/月。作为已核实的低价起步选项，地域、库存、账号资格和结算价以实际购买页为准；不能把中国内地的新客年付活动直接当作香港的可购价格。模型用量、域名及备份另计。

购买后依次执行：目标机安全配置与不可变镜像预检 → 私有初始化及 HTTPS → 云端真实生成/测试/双签 → 服务与主机重启验收 → 关闭个人电脑后移动网络验收。随后继续原完整功能追踪；全部交付门槛达到后再同步 GitHub。
