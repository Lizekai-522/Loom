# Loom 0.17.5 问题审查与修复记录

2026-10-28。本轮依据[修订后的项目策划书](project-plan-2026-10-28.md)先核对0.17.4，再推进已批准计划一致性。原始失败输出保存在源码之外的本机工作目录；这里记录问题、处理和验证范围，不包含密钥或用户业务数据。

| 发现 | 处理 | 验证重点 |
|---|---|---|
| 已批准计划的合同和实际调度任务是两份数据；任务的依赖、优先级、通道或归属发生变化时，旧版可以按变化后的任务投影调度 | 在同一数据库快照中重建批准合同并核对实际任务；领取、执行前预留和输入读取均拒绝不一致 | 独立测试直接修改临时测试库，确认无法领取、预留、产生副作用或写入新事件；不把受信数据库管理员的全部权限视为已隔离 |
| 已批准任务的工作流投影整体丢失时，旧逻辑可能将该 run 当成旧版非托管任务，重新开放旧入口 | 缺少投影时检查原始 run 事件及其摘要；原事件标记托管工作流则拒绝旧入口和领取 | 临时数据库删除投影后，领取和旧增任务均应拒绝；正常旧版非托管任务继续兼容 |
| 最初加固使执行上下文与旧审查路径提前返回不同错误 | 使用专门的计划绑定冲突类型，并在上下文边界保持原有上下文错误；异常依赖保留可识别错误语义 | 上下文、审查、调度及完整回归重测；失败未转为跳过 |
| 原临时公网隧道在服务端失效 | 核对队列空闲和进程身份后只重建隧道，保留数据库、访问码及旧日志 | 本机HTTP和公网登录、源码读取、退出与租户隔离复测；临时地址变化 |

## 安全与实现边界

计划检查覆盖本机 SQLite 中已批准工作流的合同、任务身份、依赖、归属、标题、优先级与通道；领取和已有租约的执行/预算入口在各自事务中核对。事件链和数据库本身仍属于本机受信边界，不能据此宣称抵御拥有数据库写权限的攻击者，也不能外推为 PostgreSQL 生产适配器或多主机一致性。

用户原有62项需求继续保留。第二独立模型仍待配置，任务不因此取得签名或最终成功；完整人工裁决、画布、通用Rewire及生产身份均未完成。本轮新增实现与历史真实模型/沙箱证据分开登记，测试中的模型替身不计为真实模型调用。

具体完成状态和测试数量以[本轮验证记录](validation-0.17.5.md)为准。

升级辅助程序在启动子进程后因继承输出管道而未退出；核实身份后仅停止该辅助程序，保留已启动的服务和隧道，并修正辅助脚本以避免管道继承。随后独立复测本机、公网及数据库，结果见验证记录。该辅助脚本未再次执行整套升级。
