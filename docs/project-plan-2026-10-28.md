# Loom 项目策划书：第四轮审查修订与实施计划

修订日期：2026-10-28。本文由《Loom 方案书第四轮评审裁决与改写规格》依据项目现状和复审结果修订，作为后续项目策划与实施的当前依据。报告中的建议已按本项目现状重新裁决；它们不等同于已实现或已验收。

## 1. 基线、目标与适用范围

- 已有方案基线：[Loom v2.1](Loom.md)，保留其 FR-001—FR-062、R01—R24 与相关安全约束。本文是经复审的新实施计划；与旧计划相冲突的实施顺序以本文为准，原方案原文和编号不被覆盖。
- 本轮起始实现基线：0.17.4，单机 SQLite、中文回环工作台、独立受邀公网体验、Flash 与受限 Docker 任务链。生产 PostgreSQL 适配器、完整人工裁决和第二独立模型仍未完成。
- 本次材料引用的 v3.1 方案全文、完整十八条原始意见没有在现有基线中找到。涉及该版本的具体章节、FR-069／074／083、15条 ADR 和所谓25天工期均标记为**待原文核对**，不虚构现有章节或验收结果。
- 保持项目功能完整性的目标。画布、审计分链、工具、上下文、配额和完整人工裁决按阶段建设；暂未实现不等于放弃。第二模型按用户决定先待配置，未独立验证的产物保持 submitted，不生成虚假签名或最终成功。
- 临时公网由本机独立体验服务和 Cloudflare Quick Tunnel 提供；工作台自动操作员端口只绑定回环，不能直接向公网转发。体验码、模型密钥、内部身份与数据库保存在源码之外的私有目录。

### 2026-10-28 实施进展

0.17.5 已完成 S1 的一部分：领取与执行入口在同一 SQLite 事务中核对已批准计划和调度任务，工作流投影丢失时拒绝降级。完整本地套件 974 项主测试、382 项子检查通过；独立新增排队篡改专项和真实 Docker/JetStream 12 项通过。模型替身不构成真实模型验收，第二模型仍待配置。S1 其余内容及后续 S2—S5 尚需逐项建设，不能据此认定项目完整。详见仓库内 `docs/validation-0.17.5.md` 和 `docs/review-0.17.5.md`。本文中的相对链接以仓库 `docs` 目录为基准。

### 0.17.6 恢复条件检查

S3 的本机人工处理增加中文只读恢复预检，与实际恢复共用同一规则和事务内计划校验；不会自动执行、判定成功或替代双签。该项属于 FR-024、FR-058、FR-056 的局部推进，完整人工裁决、告警、独立身份和生产恢复仍待实施；详见 `docs/validation-0.17.6.md`。

### 0.17.7 人工核对证据一致性

S2/S3 局部加固：人工核对不得将部分状态或已保存结果的调用判为未发送；保留原始证据及预算预留。中文工作台提示冲突，实际提交仍由后端事务检查。历史数据仅对现有结果及可识别事件做只读检查，不能推断已经丢失的证据。详见 `docs/validation-0.17.7.md`。

### 0.17.8 未结算预留恢复

S2/S3 局部加固：已保存调用结果但预留未结算时，租约过期不自动重试；具名操作员可凭外部依据核对用量，随后单独决定恢复，原预算和尝试次数仍生效。未关联到受支持模型调用的预留继续冻结，不能自动释放。详见 `docs/validation-0.17.8.md`。

### 2026-10-29 上线目标与 0.17.9

用户要求今日 18:00 左右上线，每版本完成测试、更新 GitHub 并核对后继续。优先维护受邀公网入口和真实浏览器主流程；本机临时隧道不能作为稳定生产托管保证，独立网络复测和生产门槛仍需确认。0.17.9 修复公网浏览器登录与暂停/恢复/终止入口，账务人工核对仍限制在本机；详见 `docs/validation-0.17.9.md`。

### 0.18.0 宿主验收诊断与真实链路

S2/S3 局部推进：可信宿主验收事件增加脱敏的结果计数，人工待办显示失败类型；新增统计与摘要不包含用例名称、输入或输出，历史事件无需迁移。0.17.9 已在隔离库通过真实 Flash 分析、精确辅助输入批准、代码生成和 6 项 Docker 用例，独立双模型仍待配置。详见 `docs/validation-0.18.0.md`。

### 0.18.1 排队等待提示

浏览器对同一排队请求持续观察超过 10 秒时提示检查本机执行器或继续等待，保留取消操作；不将等待提示当作进程健康证明。详见 `docs/validation-0.18.1.md`。

### 0.18.2 临时公网只读检查

上线前可检查受邀入口的已登记进程、Docker 服务、本机入口与临时 HTTPS 登录页；不发起模型调用。曾有一次 HTTPS 检查失败，随后复测通过，原因未确定；正式体验前仍需独立网络复核。详见 `docs/validation-0.18.2.md`。

### 2026-10-29 独立移动网络确认

用户反馈“移动网络访问成功”，当前受邀入口的手机独立网络访问待办关闭。收到反馈后本机只读检查七项再次通过；不把该反馈扩展成完整手机业务或独立模型验收。见 `launch-readiness-2026-10-29.md`。

## 2. 二十一行意见的修订裁决

“采纳”表示作为后续设计要求；“已有局部”表示存在可复用基础，并非完整验收；“待原文”表示不能核实原报告的被审条文。“新增-C”与第14条是同一个诊断码问题，不按两个独立功能重复计数。

## 3. 分阶段实施与验收

每步遵循“先测基线→记录问题→实现→专项与必要回归→更新证据”，不把测试替身、历史通过或源码存在等同于当前真实验收。

1. **S0 基线与可用性。** 核对当前服务、队列、原数据完整性、模型与预算；修复临时隧道失效时只替换已确认进程，保留访问码、数据和日志。验收覆盖匿名拒绝、受邀登录、读取、退出及私有配置边界；独立手机网络需另行现场确认。
2. **S1 已批准计划一致性。** 审核并加固实际任务依赖、计划摘要、任务身份、权限和调度通道的一致性；在派发及执行的事务边界拒绝已变更或非法绑定。保留现有 Task ID 和历史计划，测试正常、篡改、并发、旧计划和跨租户路径。
3. **S2 审计、预算与恢复。** 复用现有连续事件链、outbox、reservations 和 PG RLS；按真实缺口设计状态迁移和对账。链头连续、幂等、unknown 保留和超预算冻结均须独立验收；状态或执行变化须验证真实基础设施。
4. **S3 人工裁决、上下文、工具和配额。** 在既有角色授权与审计边界上逐项交付；人工例外不得伪装成独立验证通过。每项同时提供中文操作入口、测试和失败恢复说明。
5. **S4 画布与推测执行。** 在取得新版原方案或完成明确的需求映射后实施；先建立结构化节点、纯编译和可解释诊断，再接受限预览、可靠传输、依赖图及验证。推测产物不得绕开硬门禁或向外产生不可撤销副作用。
6. **S5 部署与完整验收。** 独立模型及受信身份、恢复演练、权限隔离、供应链、监控、性能和原FR逐项验收；未通过的项目保持待配置或未完成，不能以演示替代生产验收。

截至本修订日，25天仅为原报告提议，缺少完整输入、人员和关键路径，不能承诺该工期。10月28日公网体验是已知交付要求；长期功能按用户要求继续建设。

## 4. 审查、测试与事实来源

- 2026-10-28 复审在内存复现 `head_seq < seq` 跳号及冲突静默忽略；执行纯 Gate-V 反例确认未双签不通过；核对现有 Task ID 不可解析为 UUID。
- 只读PG目录查询显示21张 Loom 测试表启用并强制RLS，应用、网关、审计等角色没有 superuser 或 BYPASSRLS；这不是生产写入或多租户部署验收。
- 报告原表中各分区“覆盖章节”列没有精确重复，但同一意见涉及多个章节，实施时每章指定唯一负责人并核对跨章语义，不按意见盲目并行覆盖。
- 原补充批注的“先Rewire生效、失败再回滚”“失效传播只到两层”“状态快照必然破坏纯函数”不直接采纳；原文提到的§3.2.1已在裁决表中列出，不能称为完全遗漏。
- [Cloudflare Quick Tunnel 限制](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/#limitations)；[PostgreSQL行级安全](https://www.postgresql.org/docs/16/ddl-rowsecurity.html)；[PostgreSQL策略定义](https://www.postgresql.org/docs/16/sql-createpolicy.html)；[EventSource标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)；[npm许可证字段](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#license)；[OmO 5.1.48 发布包](https://registry.npmjs.org/oh-my-openagent/-/oh-my-openagent-5.1.48.tgz)。
