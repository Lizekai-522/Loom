# Loom 0.23.0 审查与修复报告

起点0.22.0源码、运行服务与GitHub逐字一致，1199主/387子、真实基础设施40项、Chromium17项和66项运行检查通过。发现reviewer可产出有来源的意见，但独立验收只接程序及需求/设计/公开检查，reviewer任务无法在可信门槛下完成。

新增第一层审查质量复核，复用v2类型引用并纳入review-findings。原意见和其引用的原产物/冻结需求/宿主摘要共同绑定，源材料变化先停止。原需求投影须匹配创建事件，不采信意见自报的验收结论。增加明确的递归边界，防止任意深度重复展开；上下文仍执行原静态字节上限，不静默裁剪。

前端只补必要的意见复核及原始材料查看/导出，未进行整套换皮。隐藏终验仍不进入复核请求，意见通过不代表原程序通过，也不触发fixer授权。独立人工仲裁、validator及完整功能边界继续保留。

新增专项首轮3项通过后1项失败，原因是测试将预检阻止的返回值误认为必有task_verified字段；预检在调用模型前正确停止。已改为同时核对blocked、0请求及任务仍submitted，原失败XML保留；随后9项新专项通过。没有把失败转为skip或改宽产品放行条件。

浏览器首轮发现已完成任务不再生成新的preview，导致基于preview显示的原材料核对提示缺失。提示改按当前冻结的reviewer角色一并显示，复测17项通过，导出原始材料与绑定字节、附属文件SHA256及版本记录一致；篡改附属材料会清空旧正文并禁用全部导出。

基础设施首轮40通过/1失败，失败用例为无辅助输入的普通developer实际Docker执行，事件明确记录host_cases_timeout=1及Gate拒绝；没有把超时误计成功。当时完整回归、专项、Chromium并行运行，资源争用是可能因素，未通过性能跟踪确认根因。保持SandboxConfig.timeout_seconds=5.0与产品代码不变，单用例复测通过，随后在完整回归/浏览器结束后串行重跑整组。原失败XML另存infra-initial，完整性能/并发NFR仍待验收。
