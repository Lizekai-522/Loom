# 审查意见的独立验收

0.23.0允许对具备模型网关来源的review-findings候选提出独立复核，沿用明确申请、单次工作器、独立项目额度、Flash/Pro分别审阅和真实Ed25519验签。手动提交、伪造来源、过期版本、未决账单或变更后的原始产物均不放行。

复核审查意见不能只检查JSON结构。它核对原报告是否准确、完整地处理冻结需求，有无误报或遗漏。输入包含两个文件并共同绑定subject.source_sha256与输入摘要：

- artifact.json：原审查意见正文。
- review-context.json：被审原始产物正文、精确引用、冻结需求/指令/成功判据和可信宿主摘要。

原始需求从创建事件重建并与Goal投影核对。隐藏用例名称、输入、期望值、stdout及完整模型会话不进入文件。原审查产生时没有重新执行程序，本次意见质量复核也不执行程序；外层执行用例计数为0，原宿主摘要只属于被审原版本。

两模型分别接同一份材料，不互看首次复核结论。两个通过才能验证reviewer任务；一个通过一个拒绝进入disputed，两个拒绝为rejected。结果未知保留额度，不自动重发。期间撤销原始产物会停止后续复核，不消费旧引用。

意见质量通过不表示原程序已经满足验收，也不自动批准或运行fixer。明确发现的问题仍需具名操作员核对并批准相应修复输入，修复任务及Goal继续按原合同验收。其他任务未完成，整个Goal不会因此成功。

工作台可在审查任务的“查看正文与导出”中展开被审材料，下载review-context.json；每次下载都重新读取和核对版本。版本记录含附属材料文件SHA256，复核页展示签名和原材料核对要求。源材料变动或摘要不符时清空旧内容并关闭导出。

本轮限制：只支持对原始程序或三类文档的第一层审查做独立质量验收；不递归验证任意深度的“审查的审查”。完整人工仲裁、validator执行及通用七角色流程仍单独推进。本轮新链路采用模拟模型响应、真实签名及真实Docker验证，不能记作新的真实模型验收。
