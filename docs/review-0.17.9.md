# Loom 0.17.9 问题审查与实施记录

2026-10-29。0.17.8 基线专项 95 项主测试、23 项子检查通过。本机可访问；此前 Quick Tunnel 域名无法解析，核对队列空闲与已登记进程后重建隧道，保留访问码和数据。恢复后的匿名拒绝、受邀登录/读取/退出与数据库完整性检查 13 项通过。

发现两处真实公网流程问题：一是网关白名单使用错误的运行控制路径，页面按钮的暂停、恢复和终止请求被 403；二是浏览器提交登录表单时因 no-referrer 策略发出 `Origin: null`，被严格来源检查拒绝。此前只用手动设置 Origin 的 HTTP 客户端验证，不能代表真实浏览器登录。两个先行反例及首次浏览器失败记录已保留在工作目录。

处理：在白名单中添加实际的三项 `/control/` 路径，沿用受邀会话、同源、角色、幂等和预算/任务限制；账务核对、worker 提交和其他控制路径继续禁止公网访问。登录页面单独使用 same-origin 引荐策略，使同源表单正常携带来源，其他页面仍使用 no-referrer；不接受 null 或跨站来源。

使用独立数据库、无模型凭据的临时公网测试服务，经真实 Chromium 和 HTTPS 隧道完成登录、暂停、恢复、终止及退出；仅产生三条测试控制审计事件，零模型请求。该测试来自本机网络，不代表独立手机网络验收。体验空间使用共享访问码，当前不是生产人员身份隔离；完整人工裁决、独立第二模型及生产部署仍待建设。

最终真实基础设施测试首轮有一项 Docker 正例进入人工处理，记录显示宿主终验失败，但原记录没有保留足够的用例状态来确定具体原因。失败未删除；新增仅记录测试用例状态和耗时的诊断，单项复测通过，随后完整 Docker/JetStream 专项 12 项通过。不能把此次失败的原因确定为超时或声称根因已修复。
