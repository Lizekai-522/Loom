# 任务上下文大小上限

0.18.6 可在新计划的节点 `limits` 中设置 `context_limit_bytes`，取值为 256–262144 的整数。例如保留原金额、词元和次数预算，并添加：

```json
{"cost_limit_microusd":1000000,"token_limit":2000000,"max_attempts":1,"context_limit_bytes":65536}
```

在工作台“计划”页编辑或导入完整工作流 JSON，保存新修订并核对摘要后批准；进入“推进指引”的“工作台执行”，可在预算提示中核对上限。此字段随批准合同冻结，不能对已批准任务直接放宽。遗漏或 null 不改写旧计划和合同摘要，继续使用原网关请求体限制。

检查对象是网关实际序列化的完整 JSON 请求体，包含系统指令、输出 schema、用户需求、精确辅助输入、公开修复反馈和模型请求参数，按 UTF-8 字节精确计数。它不是字符数、词元估计或供应商上下文窗口测量。网关本身的更严格限制仍生效。

普通开发/修复、结构化角色生成和每次 Rebind 模型调用，在预算预留与 effect 发起意图之前检查上限。超限记录 `TASK_CONTEXT_LIMIT_EXCEEDED` 并进入人工处理，不发送新模型请求、不静默截断，也不归类为模型能力失败。修复首轮的已知费用保留；反馈使后续轮次超限时不再发起下一次模型调用。未知调用的原有预留规则不变。

完整上下文压缩、tokenizer、相关性裁剪、效果对照与租户/模型/工具三层配额仍未完成。该局部上限不改变保守费用预留，也不替代独立模型验收。
