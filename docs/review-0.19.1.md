# Loom 0.19.1 审查与修复报告

起点0.19.0已完整测试并发布。新增双模型私有复核和持久消费，沿用真实网关、冻结合同、金额/词元和配额，不把生成意见当作签名。已知回执经ArtifactService重建后才签名，源任务、原始需求和证据复核后与Task完成原子提交。

首测8项初始化错误源于实现误用了goals表名；已按实际workflow_goals修正，原失败XML保留。随后负面路径1项测试错误读取脱敏snapshot中不存在的output字段；改为在隔离测试库核对原始候选逐字保留，不向测试输出打印程序正文。拒绝行为本身正确。

实现复核发现Task完成会清空worker，而旧ReviewInputService仍用当前worker匹配历史提交，导致已验证源码不能读取。现从同轮唯一claim事件恢复原拥有者，并持续检查执行/提交顺序、完整事件链和精确正文；增加完成后读取、原子审计失败回滚、重启未知额度保持及跨租户反例。

最终复核补查请求记录和签名记录的事件ID/事件hash指针，拒绝正文相同但指针被替换的记录。真实Flash/Pro各一份响应和签名消费成功；历史候选6项Docker测试证据保留，程序Task完成后仍能导出。原多角色Goal有其他任务未完成，因此保持开放，不能据单个Task通过宣布整条历史流程成功。下一轮接中文请求与结果界面，并补齐常驻执行器的启动前阻断处理。
